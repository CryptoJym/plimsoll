# Dispatch binding history and adoption

A profile with 945 open bindings and 55 elapsed windows has reached the legacy 1,000-entry limit. This change keeps the open bindings and moves elapsed attribution windows into an immutable, hash-bound SQLite history image, then publishes its reference with the profile. An elapsed window does not prove that the native thread ended. Delayed events and restamp still consult the original window.

The hot limit remains 1,000 per root. History is bounded to 4,096 rows per root, 65,536 rows and 32 MiB per image, and eight retained files totaling at most 256 MiB. Old generations and orphans count against these limits and are preserved. Storage pressure refuses a new publication; it does not grant deletion or more capacity. Reads validate the exact image, schema and custody. Missing or damaged history produces unknown capacity and no attribution.

`closeDispatch(args, now, authority)` requires an authenticated terminal adapter: a completed turn, binding age, inactivity or attribution failure cannot close the native identity. The CLI `dispatch close` has no such adapter and refuses. A caller-supplied Boolean verifier in the proof suite is a fixture, not native authentication. New future binding windows refuse; already stored future windows remain hot and readable. Placement must never retry because attribution failed.

Images are durable before the atomic profile rename. That rename selects the authoritative generation. A failure afterward requires rereading the profile and validating its referenced image; rolling back the mutation-lock database does not undo the rename. The finite synchronous time checks reject late results but cannot preempt a syscall or callback that never returns.

`rollbackCollectorDispatchHistory()` materializes history only if the previous 1,000-entry schema can represent every current binding without losing terminal markers. A root with 945 open, 55 historical and one new binding is deliberately not downgradeable. Old 0.7.48 readers reject the strict additive history field. Before any shared-home migration, the release owner must authorize the change, hold older readers and writers, retain exact backup custody, qualify the current release pair and verify the lossless downgrade preflight. Mixed running versions are unsupported.

Run `pnpm proof:dispatch-history` for the 95 real filesystem/SQLite checks and `pnpm proof:dispatch-binding` for the existing CLI/capture suite. The existing suite now checks the explicit terminal-adapter refusal and preservation contract; historical pruning and unauthenticated close expectations are intentionally replaced. CI runs both. Root also qualified the unchanged named-usage rollback proof on PR450 head d141f33ec4a95acbbf5fc2ffb0e3e66f1d376e54 plus this capacity overlay, using actual previous 0.7.48 and 0.7.47 readers. A later PR450 head requires requalification.

This source change does not implement the native terminal adapter, generation cleanup authority or fleet rollout. It preserves collector version, account/auth logic, outbox authority and original release ownership. No live profile, collector installation, native job or provider state was changed by its source review.
