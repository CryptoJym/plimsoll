## 5. Assumptions B0 made on the lead's behalf (decide ambiguous points, report them)

- **The fact is keyed by the ledger, not by the named install alone.** The brief's example (key by the named install, keep the foreign-tenant protection) gives one answer per row but reopens review r2's R7: any install of the tenant could pre-poison another install's next versions by naming them (never a misattribution, but a denial of attribution bounded only by the cap and repaired only by a rebind). The reader's option 1 (the uploader and the installs it replaced) keeps R7 closed but, taken literally, is one-directional: a fact recorded by the new install would not bind the old install's summary. Keying by the **ledger**, the first install of the chain, is the smallest rule that is symmetric (X and Z read one fact, whichever recorded it), keeps R7 closed (another Mac is another ledger), keeps the foreign-tenant rule, and changes one column and one key. The join records the link with **proof of possession of the previous install's key** (an HMAC over the token; the collector still holds the key when it posts the join, `join.ts:201-238`), so lineage cannot be claimed by a hostile joiner who lacks it; a join without a verifiable link starts a new ledger and is disclosed, which is where the old split can still appear (a faulty stamp on an unlinked re-join), stated rather than hidden. An honest B2a collector always links when it has a previous install.
- **Lock, then read, is stated as a property of the call, and the route's use of it as text.** A pending proof can show that `loadSightingView` locks first and returns a consistent view (case 5 does: the view waits for a held `FOR UPDATE` and carries the version with its audit row, which a rows-before-lock loader cannot), and can replay the reviewer's ordering through it. It cannot bind where a future route *calls* it; C6 requires the call in the judging transaction and C7 says B6's review must read the route. The measured PostgreSQL behaviour (a `FOR SHARE` requested while a `FOR UPDATE` waits is granted at once) is recorded in C1, because it shapes what a test can observe: a sighting waits only for a rebind that holds the row.
- **The erasure child.** `eraseTenant` cannot address a private cluster from the test process without product changes to `db.ts`; the child process with `DATABASE_URL` set is the smallest test-side repair, and the probe shows today's `eraseTenant` erases the disposable tenant with zero residue through it.
- **The Postgres proof's R5 case keeps its sequential half and adds the mirror order** rather than replacing it, so the wait the read confirmed (`pg_blocking_pids`) stays observed and the discriminating schedule is added.
- **Test 8 drives `performJoin` (the full join) rather than `resumePendingJoin` with a hand-written pending file**, because the join's pending-file shape is private to `join.ts`; the fake cloud answers the join route with a grant and the handshake with `accepted: 1` through the repository's own `acknowledgingFetch` fixture, as `scripts/join-isolation-proof.ts` does. The guard proves this set-up on today's code.
- **New collector surfaces are pure helpers** (`actorBindingStatus`, `partitionFloodRefusal`, `seedJoinedInstall`) so the low items have a test each without a live server; their names are handles, the behaviour is the contract (C6's rename rule).
- **The lifecycle rule is tested in the fixture against "what the round-9 text permitted"** (a view built from active installs), the same way the lock-order check is; both are labelled as such in the check text.
- **`ARCHITECTURE.md`'s title is corrected and says which rounds' edits it carries**; `PROOF.md` and `BUDGETS.md` keep their round-8 titles because nothing in them changed in rounds 9-10.

#### Round 6, in plain words (moved here from SUMMARY-FOR-JAMES.md)

- **A summary of each day can now be acknowledged by the cloud.** Deleting a raw row requires the cloud to have acknowledged every summary that used it, and one of those (the per-day summary) had no way to be sent or acknowledged, so in practice nothing would ever have been deleted. The upload protocol now carries it and acknowledges it like the others. Test: `b1_day_target_receipt`.
- **Who owns activity captured while a Mac was offline is now the same answer whether or not it reached the cloud.** If an admin re-binds a Mac from person A to person B while it is offline, last round's rules could export the same activity as A's if it never uploaded and as B's if it did. Now both paths use the same stamp the collector wrote at capture, the cloud records when the Mac acknowledged the change, and the answer no longer depends on delivery. Test: `b4_offline_rebind` (seven orderings, the reviewer's included).
- **Every timestamp the collector accepts now reaches the day totals.** The collector accepts some unusual but valid timestamp formats; last round's plan would have dropped those records from the dashboard's day sums as "contract violations". They are now folded into their real UTC day, and "contract violation" is reserved for a value the parser truly cannot read, which is then listed by id, never dropped silently. Test: `b5_non_iso_day_facts`.
- **The disk-runway check before a Mac's no-delete hold used a stale growth figure.** The temporary tables the migration adds are about **59% of the raw table on Studio1, not 42%**, once the per-row identity and link rows are counted. The gate now computes the figure per Mac from its measured row counts, with a safety margin, and a rehearsal copy replaces the estimate on the busy Macs and Studio0. Test: `s1b_runway_geometry` (a Mac whose hold the old figure would have started and the corrected one refuses).
- **The "unread file" rule is now the same in the bead and the acceptance drill as in the design.** An unparsed session file keeps a Mac's coverage "unknown" through the present, not just up to the file's last write. Test: `b22_false_complete`.
- Also: a source that reports no cache tokens but sends some anyway is treated as ambiguous rather than counted (`sf_no_cache_columns_guard`); the size check after an aborted migration allows for the raw rows captured meanwhile (`sf_abort_rebuild_bound`); the two tailer fixes are tracked in collector 0.7.42; deleted usage rows count as tombstones too; the fleet half of dispatch tagging stays parked until its owner accepts the interface; and the timestamp proof is described honestly as a large finite corpus with a conservative census.
