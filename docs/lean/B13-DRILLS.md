# B13 maintenance rebuild drills

This contract follows `BEADS.md` B13, `MIGRATION.md` §4 and `PROOF.md` §5 item 2b and §6. A copy drill uses `cp -cR` on the whole kept directory, verifies the cloned `work-ledger.sqlite` hash, and runs only on that clone. The `--copy-drill --copy-root` route never grants a live migration stage. A live invocation requires the `lean_rebuild_stage` receipt in `maintenance_state` with value `S10` or `ABORT`; the B2a migration owner must write that receipt when its stage gate is met. Until then the live preflight refuses with `stage_not_ready`.

## Writer pause and recovery boundary

The daemon and its maintenance and enrichment children own the target ledger connections. Before opening SQLite, `LocalEventBuffer` creates an open token and checks the rebuild gate; it then records one named lease per module in `maintenance_state`. Close releases both. A stale token fails closed and needs an operator to verify that its PID is gone before removing it. The rebuild first checks the stage, integrity, outbox count and headroom, using the greater of the operator WAL receipt, the last 24 hours of recorded WAL samples, and the current WAL file. It refuses a live run without a recent WAL sample. A headroom refusal is stored beside the ledger and surfaced as `maintenance.rebuild` in daemon `/status`; the receipt names reclaimable, required and shortfall bytes. The rebuild starts a ledger-free pause listener, unloads the daemon through the existing lifecycle authority, waits for the listener to bind, and refuses if any lease, token or file handle remains. The pause listener authenticates and durably spools admitted hooks and OTLP, then returns `503` and `Retry-After: 1`; `/status` declares `maintenance_rebuild` and a null claim `through`. Once the file is swapped, the durable state becomes `resume_started` before the listener is released and the daemon is loaded. That boundary makes the old file forensic evidence: `--rename-back` and `--recover` refuse with `forward_repair_only`.

On an interrupted `VACUUM INTO`, `--recover` checks the untouched source, discards the incomplete target, and resumes capture. A failed target verification also discards the target. A failed reopen after swap renames the old file back before the writer gate opens. The five dashboard snapshots are regenerated from the rebuilt projection rows at their original publication times and compared with the source publication; only the two work counters advanced after publication are excluded. Finance publication controls, schema hash, user version and every retained table count must also match before the swap; the reopened file runs `integrity_check` again. The Studio0 incremental backup alternative is a separate mode to select only if the rehearsal measures a plain rebuild pause above 15 minutes: copy pages while capture continues, then run a final catch-up and the same verify/swap/rollback boundary under the full pause. It requires a separate correctness drill for pages changed during the concurrent copy.
